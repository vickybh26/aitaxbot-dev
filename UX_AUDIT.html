The one-paragraph version

All four P0s and five of six P1s are closed and re-verified against current source — the broken token layer, the mobile bottom-edge z-stack, the contradictory data-storage copy, the print blackout, the contrast failures, the Hindi toggle, the three competing design specs, the hand-rolled modals, and the stale FAQ. One P1 (the two-grey-ramps finding) is only half done: gray is fully retired, but the underlying imbalance between plain Tailwind blue and the brand's own persian-blue was never codemodded sitewide — only the header and two pages were touched. Two P2s (hardcoded hex, unlabelled inputs) and one P3 (loading spinners) are partially fixed for the specific case originally cited, with a smaller residual left over. One P2 — small badge/pill type sizes — was never touched: it has grown from 9 to 20 instances since the original count, because new badges were added elsewhere in this same fix session without anyone re-running the grep.

P0 RESOLVED The shadcn token layer was broken at the root — every Card and outline Button rendered wrong Design system · affected 88 Cards, 58 Buttons, 32 other usages ›

Original finding. tailwind.config.ts mapped shadcn tokens straight to bare HSL custom properties (primary: "var(--primary)") instead of wrapping them in hsl(), so the emitted CSS (background-color: 0 0% 100%) was invalid and did nothing. Cards, outline/secondary/destructive/ghost buttons and every focus-visible:ring-ring were silently dead.

Verified 10 Aug

Every token in tailwind.config.ts — background, card, popover, primary, secondary, muted, accent, destructive, border, input, ring — is now wrapped in hsl(var(--x)). The integrity re-check on 9–10 Aug additionally found and fixed two tokens (chart, sidebar) left unwrapped in the first pass; confirmed dormant (no --chart-N/--sidebar-* variables declared anywhere, zero .tsx usage) but wrapped for consistency with the rule.

What's working — including what the fix session added

Genuine strengths, old and new

  • The token layer is now real. Every shadcn token is correctly wrapped in hsl(); Cards and outline Buttons render as designed for the first time.
  • ModalShell is a solid, from-scratch accessibility primitive. Focus trap, Escape, scroll lock and focus restoration, applied consistently across 6 consumers rather than each modal reinventing (or skipping) the pattern.
  • The colour rationale is right, and is now backed by an honest single source. Three competing specs are down to one, with the other two clearly marked historical rather than silently ignored.
  • Fixes are commented with the "why," not just the "what." Nearly every change reviewed left a comment explaining the prior bug and the reasoning for the new approach — genuinely useful for the next person, and part of why this re-verification was possible to do quickly.
  • An honest self-audit caught two of its own false claims. The integrity review found that two findings (the AIS naming/aria-current gap, the design-spec archival) had been reported as fixed in commit messages without being in the diff, and corrected both rather than letting the discrepancy stand.
  • tabular-nums on money, sensible lazy-loading, the footer as reference surface — all noted in the original audit, all still true.

Method. This is a re-verification, not a fresh audit. Every one of the 26 findings from the 7 Aug audit was re-checked against current source with a fresh grep/read, not by trusting prior commit messages — which is precisely how the two initially-false "fixed" claims were caught. Contrast ratios were recomputed from scratch via a Python script implementing the WCAG 2.1 relative-luminance formula, not carried over from the original table. Not covered. Server-side code, tax-calculation correctness, real-user performance metrics, live cross-browser or on-device rendering — the bottom-edge z-stack fix in particular is verified against declared CSS geometry, not a physical-device screenshot.
